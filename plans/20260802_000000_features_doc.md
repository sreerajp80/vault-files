# Create docs/features.md

**Status:** completed

## Files to change
- `docs/features.md` (new file)

## What the issue is
The user wants a single, accurate file listing everything the "Vault Files" app does today. This is meant to be shared with an LLM (in a different project) so that assistant can see what this app already offers before building similar features elsewhere. No such file exists yet.

## Plan for the fix
1. Write `docs/features.md` with:
   - A short description of what the app is (secure file/storage manager, Kotlin + Compose, single module, MVVM).
   - A clear note up front on the app's current maturity: most file operations and storage analytics are real; the "Vault" and "secured folders" are access-control gates, not real encryption; only Secure Notes use real AES-256-GCM encryption; PINs are stored in plain text; no AI/network features are wired up despite scaffolding.
   - A full feature list grouped by area, matching the app's own structure:
     - App shell (tabs, app lock, theming, permissions flow, share-in/pick-mode/view intents)
     - Storage Analyzer tab
     - File Explorer tab (browsing, search/sort, view modes, all file operations, previews, secure notes)
     - Secured folders ("shielding")
     - Secure Vault tab
     - Secure Notes encryption
     - Settings (Display, Security, Help, Permissions, About)
     - Cross-cutting infrastructure (DocumentsProvider/SAF, localization, theming)
   - Each feature marked plainly as real behavior vs. a security-related caveat, so the reading LLM does not overstate what the app secures.
2. Base the content on a full codebase read (already done) of `MainActivity.kt`, `StorageViewModel.kt`, `StorageRepository.kt`, all `ui/*.kt` screens, `data/CryptoManager.kt`, `data/VaultDocumentsProvider.kt`, `data/DatabaseEntities.kt`, `AndroidManifest.xml`, and existing `docs/architecture.md` / `docs/build.md`.
3. Write a change log entry in `change_log/` after the file is created.

No app code changes — documentation only.
