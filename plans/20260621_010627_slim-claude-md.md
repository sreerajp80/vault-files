# Plan: Slim down CLAUDE.md by offloading detail to on-demand docs

## Issue

`CLAUDE.md` is loaded into context on **every** session. Right now it is fairly long
(~110 lines covering build commands, build gotchas, namespace caveats, full architecture, and
conventions). Much of this detail is only needed when actively working on a specific area, so it
inflates the baseline context window for every task.

## Goal

Keep `CLAUDE.md` short — only the high-signal facts every session needs — and move the deeper
reference material into separate files under `docs/` that Claude reads **only when relevant**.
`CLAUDE.md` will point to those files so future instances know they exist and when to load them.

## Files to be changed / created

1. **`CLAUDE.md`** (rewrite, shrink) — keep:
   - one-paragraph overview + the "simulated demo data / no live AI" warning (critical, cheap),
   - the namespace caveat (3 IDs) — small but high-impact footgun,
   - the most-used build/test commands (assemble, install, unit test, single test),
   - a short "Architecture in one paragraph" summary,
   - a **"Detailed docs (read when relevant)"** index linking to the files below.

2. **`docs/build.md`** (new) — full build/test detail moved out of CLAUDE.md:
   - Roborazzi screenshot record/verify tasks, lint, connectedAndroidTest,
   - signing gotchas (`debugConfig` keystore, release env vars),
   - secrets plugin / `.env`, config-cache notes, SDK/JVM versions.

3. **`docs/architecture.md`** (new) — full architecture + conventions moved out of CLAUDE.md:
   - layer-by-layer breakdown (MainActivity, StorageViewModel, StorageRepository, Room, utils),
   - the "conventions worth following" section (adding a preference, action→repo→message→refresh
     flow, testTag convention, session-based unlock model).

No source code (`.kt`), Gradle, or manifest files are touched — this is documentation only.

## Plan for the change

- Create `docs/` folder.
- Write `docs/build.md` and `docs/architecture.md` with the content currently in CLAUDE.md
  (verbatim where possible, lightly re-headed).
- Rewrite `CLAUDE.md` down to ~30–40 lines: overview warning, namespace caveat, core commands,
  one-paragraph architecture, and a pointer list:
  - "For build/signing/test detail, read `docs/build.md`."
  - "For architecture and code conventions, read `docs/architecture.md`."
- Keep the mandated `# CLAUDE.md` header prefix intact.

## Net effect

Per-session baseline context drops to the essential facts; the detailed material is one Read away
when a task actually needs it.
