# Plan: Enable AndroidX in gradle.properties

## Issue

Gradle reports a warning during configuration:

> Configuration `:app:debugRuntimeClasspath` contains AndroidX dependencies, but the
> `android.useAndroidX` property is not enabled, which may cause runtime issues.

The project depends on many AndroidX libraries (Jetpack Compose, Room, `androidx.biometric`,
`androidx.core:core-ktx`, lifecycle, activity, etc.), but `gradle.properties` does not set
`android.useAndroidX=true`. Without this flag, the Android Gradle Plugin does not officially
operate in AndroidX mode, which produces the warning and risks runtime issues.

Verified: `useAndroidX`/`enableJetifier` do not appear anywhere in the project's source/config
(only inside generated `build/reports/...` HTML). So the property is genuinely absent.

## Files to change

- `gradle.properties` — add the `android.useAndroidX=true` property.

## Fix

Add the following line to `gradle.properties` (next to the other `android.*` settings, e.g.
after `android.nonTransitiveRClass=true`):

```properties
# Use AndroidX (Jetpack) artifacts. Required because all project deps are AndroidX.
android.useAndroidX=true
```

Notes / decisions:
- **Jetifier NOT enabled.** `android.enableJetifier=true` is only needed to convert legacy
  `com.android.support:*` dependencies to AndroidX at build time. This project has no such
  legacy support-library dependencies, so Jetifier is unnecessary and would only slow builds.
- This is a build-config-only change; no Kotlin/Java source is touched.

## Verification

After the change:
- `./gradlew assembleDebug` (or a Gradle sync) should no longer emit the AndroidX warning.
- Build should still succeed (subject to the existing `debug.keystore` requirement noted in
  `docs/build.md`).
