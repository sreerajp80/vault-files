# Plan: In-app image preview with a gating setting

## What the user asked for
- Add an **image preview** feature: tapping an image file opens it inside the app.
- Support **as many image types as can be decoded** — not a short hardcoded allowlist.
- Add a **setting** that gates the feature — when enabled, image files get a preview;
  when disabled they keep the current behavior (a "Viewing: …" toast). The preview is
  scoped to images only; other file types are unaffected.

## Why "all image types" has a real limit (decoder, not view-vs-edit)
Displaying an image still requires **decoding** its bytes into a bitmap, and decoding is
format-specific. The platform decoder (which Coil uses) covers JPEG/PNG/GIF/WebP/BMP, plus
HEIC/HEIF (API 28+) and AVIF (API 31+). Coil add-ons add SVG and animated GIF/WebP. Formats
like camera RAW, PSD, TIFF, and JXL have **no reliable built-in Android decoder**. So the
approach is: be maximally permissive and **attempt to decode anything**, degrading to a
clean "can't preview this format" state when no decoder exists — rather than restricting to
a short list up front.

## Current behavior (the gap)
In [FileExplorerScreen.kt](app/src/main/java/com/example/ui/FileExplorerScreen.kt#L610-L635),
`onItemClick` for a plain file ends in an `else` branch that only dispatches a
`msg_viewing_file` toast. There is no viewer for images. The project already lists
**Coil** in the version catalog (`coilCompose = "2.7.0"`) but the dependency is
**commented out** in [build.gradle.kts](app/build.gradle.kts#L128). Image files are
already categorized as `"Image"` by `getCategoryForFile` in
[StorageRepository.kt](app/src/main/java/com/example/data/StorageRepository.kt#L268-L279).

## Design decisions
- **Library:** use Coil (already in the catalog). Add the **coil-gif** and **coil-svg**
  decoders so animated GIF/WebP and SVG also render, on top of the platform decoder
  (JPEG/PNG/WebP/BMP/HEIC/HEIF/AVIF). An `ImageLoader` with these decoders is built
  locally in the preview composable via `remember` (no Application class needed).
- **Broaden the "Image" category** in `getCategoryForFile`: add `jfif, heic, heif, avif,
  ico, tif, tiff` and common RAW extensions (`dng, cr2, nef, arw, orf, rw2`) alongside the
  existing `jpg/jpeg/png/gif/webp/bmp/svg`. This widens what's eligible to preview and,
  as a side effect, makes Storage Analysis count these as images (a correctness
  improvement). Anything categorized "Image" is handed to the decoder to attempt.
- **Attempt-anything + graceful fallback:** the preview always hands the file to Coil; if
  no decoder can handle it (e.g. a RAW with no embedded preview), the dialog shows a
  "Can't preview this format" state instead of crashing.
- **Setting semantics & default:** new preference `image_preview_enabled`, **default
  `true`** (feature works out of the box; user can turn it off). Lives in the
  **Display & Themes** settings sub-page next to "Show Hidden Items".
- **Preview UI:** a full-screen `Dialog` with a dark scrim, the image centered
  (`AsyncImage`, `ContentScale.Fit`), the filename at the top, and a close button.
  Loading shows a spinner; decode failure shows a broken-image icon + message. Tapping
  the scrim or the close button (and the system back gesture, via the Dialog) dismisses.
- **Trigger:** in `onItemClick`, before the final `else`, add: if
  `item.category == "Image"` **and** `imagePreviewEnabled` → `viewModel.openImagePreview(item)`.
  When the setting is off, images fall through to the existing toast.

## Files to change
1. **gradle/libs.versions.toml** — add `coil-gif` and `coil-svg` library aliases
   (reuse the existing `coilCompose` version ref).
2. **app/build.gradle.kts** — uncomment `implementation(libs.coil.compose)` and add
   `implementation(libs.coil.gif)` + `implementation(libs.coil.svg)`.
3. **app/src/main/java/com/example/data/StorageRepository.kt** — add
   `getImagePreviewEnabledFlow()`, `isImagePreviewEnabled()` (default `true`), and
   `saveImagePreviewEnabled(enabled)`, mirroring the existing settings helpers; **and
   broaden the Image extension set** in `getCategoryForFile`.
4. **app/src/main/java/com/example/ui/StorageViewModel.kt** —
   - add `imagePreviewEnabled` StateFlow + load it in `init`;
   - add `updateImagePreviewEnabled(enabled)` (persists + message);
   - add `_openImagePreview: StateFlow<FileItem?>` with `openImagePreview(item)` /
     `closeImagePreview()`.
5. **app/src/main/java/com/example/ui/FileExplorerScreen.kt** —
   - collect `imagePreviewEnabled` and `openImagePreview`;
   - route image taps to `openImagePreview` when enabled;
   - add a private `ImagePreviewDialog` composable (Coil `AsyncImage` + local
     `ImageLoader` registering the GIF/SVG decoders) rendered when `openImagePreview != null`.
6. **app/src/main/java/com/example/ui/SettingsScreen.kt** — add an "Image Preview"
   `SettingsTile` with a `Switch` in the `"display"` page (after Show Hidden Items),
   wired to `viewModel.imagePreviewEnabled` / `updateImagePreviewEnabled`.
7. **app/src/main/res/values/strings.xml** — add strings: setting title/subtitle,
   preview close content-description, load-error message, enable/disable toast messages.
8. **app/src/main/res/values-ml/strings.xml** — add matching Malayalam translations so
   the two resource files stay in parity.

## Notes / non-goals
- Loads from the local `File` only — no network, no new manifest permissions. Device
  source already requires All-Files-Access for listing, which also covers reading bytes.
- No zoom/pan gesture support in this pass (can be a follow-up); the image fits the screen.
- RAW/TIFF/PSD/JXL: attempted but may hit the graceful fallback (no platform decoder).
  Adding a dedicated TIFF/RAW library is possible but heavy — out of scope unless asked.
- No new tests added unless requested; existing Robolectric/screenshot tests are unaffected.

## Verification
- `./gradlew assembleDebug` to confirm the Coil dependencies resolve and it compiles.
- Manual: enable the setting → tap a jpg/png/gif/svg → preview opens; disable → tap an
  image → old toast shows.
