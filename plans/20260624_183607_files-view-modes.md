# Files explorer view modes: List / Grid (thumbnail) / Compact

## Issue / feature request

The Files explorer currently has a single layout: one `FileRowItem` per row in a
`LazyColumn` (`FileExplorerScreen.kt`). The user wants selectable view modes like a desktop
file manager:

- **List** — the existing row layout (default, unchanged).
- **Grid / thumbnail** — a multi-column grid of tiles where image files show a real
  thumbnail (via Coil, already a dependency) and everything else shows its category icon.
- **Compact details** — a denser single-line list for scanning many files quickly.

Decisions confirmed with the user:
- Include all three modes.
- Switch via an **icon toggle in the section header** (next to the existing Sort control) —
  a small segmented group of mode icons, tap to select directly (not a dropdown).
- **Persist** the selected mode in Room settings so it survives app restarts (follow the
  existing preference pattern, e.g. `storage_source_mode` / `image_preview_enabled`).

## Files to change

1. **`app/src/main/java/com/example/data/StorageRepository.kt`**
   - Add persistence for the new setting keyed `"file_view_mode"` (default `"list"`),
     mirroring `getStorageSourceMode` / `saveStorageSourceMode`:
     - `getFileViewModeFlow(): Flow<AppSetting?>`
     - `suspend fun getFileViewMode(): String` (default `"list"`)
     - `suspend fun saveFileViewMode(mode: String)`

2. **`app/src/main/java/com/example/ui/StorageViewModel.kt`**
   - Add `_fileViewMode = MutableStateFlow("list")` + public `fileViewMode: StateFlow<String>`.
   - Load it in the `init` block alongside the other prefs
     (`_fileViewMode.value = repository.getFileViewMode()`).
   - Add `fun updateFileViewMode(mode: String)` that saves to the repository and updates the
     StateFlow (no user toast needed — it's a visual toggle).

3. **`app/src/main/java/com/example/ui/FileExplorerScreen.kt`** (main work)
   - Add an enum `FileViewMode { LIST, GRID, COMPACT }` with a helper to map to/from the stored
     string, plus each mode's icon (`Icons.AutoMirrored.Filled.ViewList`,
     `Icons.Default.GridView`, `Icons.Default.ViewHeadline` / `Icons.Default.Reorder`).
   - Collect `viewModel.fileViewMode` and derive the current `FileViewMode`.
   - **Header toggle:** in the "All items" section-header row (currently section label +
     Sort control), insert a compact segmented control of the three mode icons between the
     label and the Sort control. The active mode is highlighted (primary tint / container);
     tapping a mode calls `viewModel.updateFileViewMode(...)`. Add `testTag`s
     (`files_view_toggle`, `files_view_list`, `files_view_grid`, `files_view_compact`).
   - **Refactor the content area:** extract the existing inline `onItemClick` logic into a
     single local `handleItemClick: (FileItem) -> Unit` so all three layouts share the exact
     same tap behaviour (unlock prompt, navigate, zip, securenote, image/text preview,
     fallback message). `onActionMenuOpen` already just sets `expandedMenuForFileItem`.
   - Branch on the current mode where the `LazyColumn` is today:
     - `LIST` → existing `LazyColumn` of `FileRowItem` (unchanged).
     - `GRID` → `LazyVerticalGrid(GridCells.Adaptive(minSize ≈ 104.dp))` of a new
       `FileGridItem` tile: square thumbnail area on top (Coil `SubcomposeAsyncImage` of the
       file for `category == "Image"`, with the existing Gif/Svg-capable loader and a
       category-icon fallback on error/loading; APK launcher icon reused via `ApkIcon`;
       locked/secured + folder icons reused), file name (max 2 lines), and small size text.
       A small overflow (`MoreVert`) in the tile corner opens the same action menu.
     - `COMPACT` → `LazyColumn` of a new `FileCompactRow`: one dense line — small (≈28.dp)
       category icon, name (`MiddleEllipsisText`, weight 1), size at the end, small overflow
       icon. Reduced vertical padding vs the list row; reuses the same icon/lock/secured logic.
   - The empty / loading / permission / category-filter states stay as-is (they wrap the
     content branch, so they're unaffected).
   - No new dependency: Coil (`coil.compose.SubcomposeAsyncImage`) is already used for the
     image preview. **Scope note:** real thumbnails are for images only; videos and other
     types show their category icon (rendering video-frame thumbnails would need the extra
     `coil-video` decoder, which is out of scope here).

4. **`app/src/main/res/values/strings.xml`**
   - Add: `view_mode_list`, `view_mode_grid`, `view_mode_compact`, and content descriptions
     `cd_view_list`, `cd_view_grid`, `cd_view_compact` (and a generic `cd_view_mode` if needed).

5. **`app/src/main/res/values-ml/strings.xml`**
   - Add Malayalam translations for the same new keys (this file is already part of the
     working set and kept in sync).

## Notes / non-goals

- Folders render the same in every mode (folder icon tile / row); only files differ.
- No change to sorting, search, category filter, hidden-items, or the action menu behaviour —
  those continue to operate on the shared `displayedFiles` list regardless of view mode.
- A change-log entry will be written under `change_log/` after implementation.
